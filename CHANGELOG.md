### Added

- Browser suite: the AR viewer page without a model (its explanation and the accessibility scan) and with one (the viewer chrome mounts, then unmounts on navigation, with no page error).
- The function-shape rules (`max-lines-per-function` 60, 150 in a component file; `complexity` 12; `max-params` 4) run at error over the whole tree (CODE-SHAPE, phase 7). The files that still fail are listed in `scripts/ci/shape-exemptions.json`, generated from the findings by `scripts/codemods/shape-exemptions.mjs --write` and refused by `pnpm lint` when a listed file passes (`--check`); `fn.shapeExemptions` in the ratchet counts the list (44 on the day it was written); it is empty and hard at zero: the rules are unconditional, and `max-lines` holds the 800-line cap in the linter as well.

Four repository probes, hard at zero: `api.bareResponse` (a Response built by hand in a handler), `api.unboundedList` (a `findMany` in a handler with neither a `take` nor the page helper), `api.rowReturn` (a server action returning an ORM row without a `select`, at once or through a local, a select carrying a secret column, or a bare boolean), `api.floatMoney` (a price made a number to send or receive it). The cursor is an opaque key of the last row's sort value and id, and the page is a keyset `where`, so a cursor from outside the filter or a deleted row cannot skip or end a list. `test/factories/prisma.ts` builds Prisma rows for the serializer tests (`serializeRestaurant` and the payloads are covered). `categoryRow`/`subcategoryRow` join the factory; the ingredients mapping and `siteOrigin` are covered.
- `abatty.probes.mjs`: `cache.serverCacheUse`, hard at zero, holds phase 5's decision that no read is cached on the server (the three `"use cache"` forms, `unstable_cache`, `cacheLife`/`cacheTag`, a static or revalidating route export, a fetch cache option, a cache store import; an invalidation is not a cache); a first cached read re-opens the phase's rules. `auth.unguardedAdminPage`, hard at zero: every page under `app/admin/(protected)` calls `requireSuperAdminPage()` first. `scripts/codemods/guard-admin-pages.mjs` (tested) put the guard into the 17 pages.
- Browser suite: a wrong password on the manager login is refused with the one message (the first sign-in step end to end, through the server action).
- `abatty.probes.mjs`: the repository's own ratchet probes. `valid.unparsedBoundary` counts the route handlers, server actions (declared, arrow or default exports) and credentials callbacks with an argument no zod parse names (ten control cases; `pnpm exec abatty ratchet --controls`); it read 40 on the day it was written and is hard at zero. `valid.wholeEnv` counts `process.env` taken whole (destructured, aliased, passed on) outside the env module, which the built-in read probe cannot see; hard at zero.
- Browser suite (`pnpm e2e`, Playwright, `e2e/`): the public menu journey (load, language toggle and memory, the dish sheet and the back button) and both sign-in pages, on a phone and a desktop project, each with an axe scan that fails on any serious or critical violation; runs against the production build, in the gate after the build, and in CI with a Postgres service seeded by `prisma/seed.ts`.

Surfaces painted with an alpha are not computed. `lib/color.ts` holds the colour arithmetic `lib/brand-color.ts` and the test share.

### Changed

- The dashboards' shell components take the portal they serve as `portal="admin" | "manager"` instead of `role` (a codemod, `scripts/codemods/rename-portal-prop.mjs`, over the eight declaring components and their twelve call sites; the phase 3 decision that deferred it); `jsx-a11y/aria-role` runs without its `ignoreNonDOM` carve-out, so a bad ARIA role on any component is a lint error again.
- `tsconfig.json` turns on `noUncheckedIndexedAccess` and `exactOptionalPropertyTypes` (TYPES-STRICT, phase 9): 140 errors fixed with real guards (an index read is `T | undefined` until the line above proves it: a first regex group, a first file, an observer entry), typed shapes where an index read stood in for one (the manifest icon triple, a per-channel colour function, the assignment field), widened forwarded props (`?: T | undefined` where a parent genuinely passes undefined), and `definedFields()` (`lib/defined-fields.ts`, tested) at the Prisma boundary so a patch with an undefined member is the same write it always was. No `any`, no `@ts-`, no non-null assertion.
- No source file is over its kind's budget (phase 8): the eight pages that were (the admin dashboard, the admin and manager create and list pages, the confirm-new-email page, the manager's dishes page, the public menu route) are composition roots of 21 to 78 code lines, their sections under `components/admin/`, `components/manager/` (one set of email-change notice primitives for both confirmation pages) and `components/shell/` (a shared list search, dish rows and stat strip for both portals' dish pages), the menu route's metadata, viewport and loader in `lib/menu-metadata.ts` and `lib/menu-loader.ts` (tested). `size.overBudget` 8 → 0 and `size.excessCode` 228 → 0, both hard; `size.overRaw` 0. - Every function meets the shape rules (phase 7, 72 findings in 44 files to zero) by extracting what a piece is for into files of their own, behaviour proven identical by rendering each old and new component to static markup under the same props and states and comparing byte for byte, and by diffing every class, string and attribute: the public menu page (`components/menu/restaurant-page/`: hero, bar, sections, the dish and filter sheets, the filter, scroll-spy and sheet hooks), the dish body and footer columns, the dashboard shell (user menu, restaurant switcher and tabs), the branding panel (preview aside, colour and appearance sections), the contact panel (fields, address, social links, preview), the sign-in flow (credentials and code steps), the font picker; the eight forms and the two category managers (`components/forms/`, `dish-form/`, `client-form/`, `restaurant-form/`, `password-form/`, `reset-password/`, `ingredients/`, one shared `category-manager/` for both portals); the four upload components on one Cloudinary browser upload, one set of file checks and one progress run (`components/upload/`), the AR and 3D viewer pages, the preview dialog and the QR display (`components/ar-viewer/`, `3d-viewer/`, `ar-preview/`, `qr/`, `model-viewer/`); the seven longest pages on header, aside and card components (`components/admin/`, `components/manager/`) with the forms' default values built in `components/forms/form-defaults.ts`; the sign-in checks in `lib/sign-in-checks.ts`; the opening-hours, social-media and JSON-LD helpers; the seed; the repository probes. `localName` (a category name in the guest's language) lives in `lib/menu.ts` with the locale vocabulary, tested there. `ar-viewer-client.tsx` is under the 800-line cap (`size.overRaw` 0), the tree's one type escape is gone (`types.escapes` 0), `size.overBudget` 34 → 8 and `size.excessCode` 5060 → 228.
- The five route handlers answer through the envelope: the users and restaurants lists are bounded and followable (sorted by name or email, then id), the two assignment routes answer `{ id, userIds | restaurantIds }`, the dish-view route answers `{ viewId, arViewed }` with a 201; failures carry `invalid_query`, `invalid_id`, `invalid_payload` (with the issues), `not_found`, `unauthenticated`, `forbidden`, `internal`. The assignment dialogs and the remove buttons use the client helpers. Every server action returns a payload it shaped, never the row: users answer `{ id, email }`, dishes `{ id, isActive, isMostPurchased }`, ingredients and categories their names and order, restaurants `{ id, slug }`, the reorders `{ count }`, the email-change confirmations `{ confirmed }`, the change request `{ sent }`. The payloads are named once per model (`lib/payloads.ts`); a delete answers only the id; a reorder counts the rows it moved. The change-email form says when the confirmation mail could not be sent instead of asking the user to check their inbox; the assignment dialogs and remove buttons tell a failure and release their control. ### Fixed

- The dish and restaurant lists' search icon carried a broken utility class (`-/2`) and sat off-centre; the three list pages share one `ListSearch`. The admins table no longer receives each admin's TOTP secret, only whether one is set. Empty table cells show `-`.
- The admin "Delete restaurant" button called `DELETE /api/restaurants/[id]`, a route that does not exist, and always failed; it calls the `deleteRestaurant` action. Creating or editing a dish returned the Prisma row, whose `Decimal` price cannot cross to the client; the actions now return plain payloads.
- Every admin page re-checks the super-admin role on each render (`requireSuperAdminPage`, one redirect table shared with the layout; five tests): Next keeps a layout mounted across client navigations, so the layout's check ran once per visit and a role change or deletion after it went unseen until a full reload. Creating, renaming or deleting a restaurant refreshes the open dashboard's shell (the restaurant switcher of the preserved layout) through `refreshDashboards()` in `app/actions/restaurant-actions.ts`, a `revalidatePath` on both portal roots, where only a rename did and only the two edit pages were named. The three `console.log` calls that printed a restaurant's patch and row (contact email, phone, address) to the server log are gone.
- Changing your own password asks for the current one and checks it on the server (the form asked, the action did not look); the new password's rules are the same on both sides.
- A mangled change-email link (a token that is not 64 hex characters) shows the "invalid or expired link" card instead of an error page; an empty sign-in field is refused with the one message instead of the server-error one.
- The migrations carry `MenuCategory.isActive` and `MenuSubcategory.isActive` (`prisma/migrations/20260920160000_category_is_active`): they had entered the schema through `prisma db push` in July 2025 and no migration added them, so `prisma migrate deploy` built a database the seed could not use (the first CI run with it). The statements use `IF NOT EXISTS`, so a database that already has the columns takes the migration as a no-op.
- The light theme's `--warning` token reads 4.6:1 on the muted surface (it was 4.11, below AA, where badges and hints paint it; `42 100% 30%` → `28%`, same hue), and the "Refresh" a guest taps for a new menu version reloads the page again (the first-visit fix had also swallowed the change of worker it asks for; unit-tested both ways).
- A first visit to a menu no longer reloads the page a second after it appears: the freshly installed service worker claiming the page was taken for an update (found by the browser suite, whose navigations it aborted).
- The manager profile's "view restaurant" link pointed at `/manager/restaurants/[id]`, a route with no page (an `as any` on the href hid it from the typed routes); it opens the restaurant's info page.
- The back button navigates through Next's router instead of assigning `window.location`.
- Three empty `interface X extends Y {}` in `components/ui/` are type aliases; the WebXR `@ts-ignore` says why it expects an error.
- `no-debugger` is an ESLint error (the gate's lint control stayed green without it); knip also watches `src/` so the dead-code control is meaningful.
- Placeholder credentials in `.env.example` and `DEPLOYMENT.md` use `<angle-bracket>` form; the real Cloudinary cloud name and API key are scrubbed from the example.
- abatty runs on Windows: `patches/abatty@0.2.0.patch` gives its npm spawns a shell (Node ≥ 20.12 refuses `.cmd` files without one).
